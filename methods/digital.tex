\section{Digital Infrastructure}
\label{sec:methods:digital}
%=========================================================

    The transport measurements in this thesis depend on more than the electrical circuit described above. Each \textit{I--V} trace also has to be associated unambiguously with the state of the surrounding experiment: amplifier gains, reference resistance, bias waveform, temperature, microwave settings, magnetic field, gate voltage, and the mechanical position of the break junction. Without this context, a recorded voltage trace would not be a reproducible physical measurement, but only a time series from the acquisition card. A central design goal was therefore to avoid relying on undocumented manual instrument settings. Before a measurement, the scripts initialized the controllable devices, applied the relevant settings digitally, and recorded their state. The measurement protocol thus defined the conditions explicitly. A new measurement did not silently inherit an undocumented setting from an earlier measurement or manual intervention.

    The digital infrastructure was therefore treated as part of the experimental apparatus. Its role was to connect instrument control, synchronized acquisition, metadata logging, and data evaluation into one traceable path from raw voltages to calibrated \textit{I--V} curves, derived \textit{dI--dV} spectra, and fitted model parameters. This section first describes the measurement architecture used to acquire and store the data. It then describes the evaluation layer that converts raw measurement records into the common data products used by the different analysis schemes.

    %=========================================================
    \subsection{Digital Measurement Architecture}
    \label{subsec:methods:digital:architecture}
    %=========================================================

        The measurements in this work were controlled by a layered Python infrastructure. The first layer, \texttt{p5control}, provided the general abstraction for instrument access, server based control, and structured data storage. The second layer, \texttt{p5control-bluefors}, adapted this framework to the Bluefors break junction setup by defining the relevant drivers, calculated diagnostic channels, and spectroscopy protocols. Together, these layers connected the physical instruments described in Sec.~\ref{subsec:setup:instrumentation-grounding} to the raw voltage traces and metadata used in the subsequent data evaluation.

        %=========================================================
        \subsubsection*{\texttt{p5control}: Instrument Abstraction and Data Acquisition}
        %=========================================================

            The experiment required a control layer that could handle many slow instruments during quasi-dc spectroscopy without turning each measurement script into a collection of device specific commands. The task of this layer was to keep instrument control, data acquisition, and metadata logging in one reproducible structure.

            The general framework for this task was \texttt{p5control}, which was developed by Florian Kayatz during his student assistant work under my supervision~\cite{kayatz_p5control}. The central idea of the framework is to separate device specific communication from measurement scripts and graphical user interfaces. Physical instruments are represented by drivers. These drivers expose the relevant control parameters and readout values in a common form, while the details of LAN, GPIB, RS-232, USB, or device specific command syntax remain hidden inside the driver implementation.

            Figure~\ref{fig:methods:digital:p5control} shows the resulting architecture. The \texttt{InstrumentServer} and \texttt{DataServer} separate instrument control from file writing, while measurement scripts and graphical user interfaces communicate with both servers through RPyC~\cite{rpyc_github}. This made the same instrument layer available for interactive control widgets and scripted measurement protocols, and it kept the file writing logic independent of individual measurement scripts.

            During operation, \texttt{p5control} distinguishes between status data and measurement data. Status data are recorded continuously. They document the slowly changing state of the setup, for example temperatures, motor position, magnetic field, microwave settings, amplifier gains, or output states. Measurement data are written when a measurement is started. They contain the time traces acquired for a specific sweep or protocol. This distinction is important because the physical context of an \textit{I--V} trace can change on a slower timescale than the trace itself.

            The measurement file uses HDF5, a hierarchical data format accessed here through \texttt{h5py}, as sketched in Fig.~\ref{fig:methods:digital:datatree}~\cite{h5py_github,hdf5_github}. It contains both the raw traces used for later evaluation and the surrounding instrument state needed to interpret them. It therefore acts as both a measurement record and a digital laboratory notebook.

            The framework coordinated slow quasi-dc measurement sequences and stored the resulting data streams in a common time indexed structure. Individual sweeps lasted several minutes, so strict timing guarantees and specialized synchronization mechanisms would have added substantial complexity without improving the acquisition. Each recorded trace could therefore be related to the continuously logged status data that described the measurement conditions. This provided the traceability required for later reconstruction and comparison of the \textit{I--V} curves.

        %=========================================================
        \subsubsection*{\texttt{p5control-bluefors}: Setup Specific Control Layer}
        %=========================================================

            The generic \texttt{p5control} layer provided the server structure, data storage, and driver abstraction, but it did not define the measurement logic of the Bluefors break junction setup. This setup required a spectroscopy oriented control layer that knew which instruments belonged to one transport measurement and which quantities had to be stored with each \textit{I--V} trace. I implemented this setup specific layer in \texttt{p5control-bluefors}, including device specific drivers, graphical control widgets, calculated transport channels, and the measurement protocols used for the data in this thesis~\cite{kayatz_p5control_bluefors}.

            The layer represents each controlled object using the same practical model, summarized in Fig.~\ref{fig:methods:digital:drivers}: parameters, values, and state. Parameters are quantities set by the user or by a measurement script, for example bias amplitude, amplifier gain, microwave source settings, heater power, magnetic field target, or motor displacement. Values are quantities read back from instruments or calculated from measured channels. State records whether a device is actively sweeping, irradiating, heating, ramping, moving, outputting, or reporting a diagnostic condition such as amplifier overload. This model keeps slow control variables and safety relevant state changes in the same status log as the measured \textit{I--V} traces.

            The primary measurement record consists of the synchronized voltage traces recorded by the acquisition card and the instrument state stored around the sweep. Together with the selected Femto gains and the reference resistance, these raw voltage traces define the later reconstruction of $V_\mathrm{sample}$ and $I_\mathrm{sample}$. In \texttt{p5control-bluefors}, the same conversion was also implemented in the \texttt{Calc} driver as a diagnostic layer for live monitoring. This layer was useful during setup work and interactive checks, but it was usually inactive during actual measurements. The \textit{I--V} curves used for analysis were derived separately from the stored raw voltage traces, as described in Sec.~\ref{subsec:methods:digital:analysis}. The remaining drivers provide the physical context of each trace: microwave amplitude and frequency, sample temperature, displacement of the break junction, magnetic field, and gate voltage. In this sense, \texttt{p5control-bluefors} connects the electrical reconstruction described in Sec.~\ref{subsec:setup:electrical} to the HDF5 data structure shown in Fig.~\ref{fig:methods:digital:datatree}.

            This connection is enforced by the measurement protocol shown in Fig.~\ref{fig:methods:digital:ivscript}. A single \textit{I--V} trace is more than a voltage ramp. The relevant gains, reference resistance, bias waveform, timing parameters, and instrument states have to be fixed before the sweep, and the synchronized voltage traces have to be stored together with these settings. The script \texttt{single\_iv.py} therefore defines one complete trace: it sets the sweep parameters, waits during an offset interval, records the sweep, and writes the acquired data and metadata to the measurement file.

            Parameter dependent measurements are built by repeating this elementary \textit{I--V} trace. The script \texttt{iv\_script.py} steps through an external parameter axis, for example microwave amplitude, frequency, sample temperature, break junction displacement, magnetic field, or gate voltage. At each point, it starts one \texttt{single\_iv.py} measurement and stores the result in the corresponding measurement path. This structure makes the resulting series reproducible because each \textit{I--V} trace is linked to the raw voltage traces and to the status of the surrounding setup at the time of acquisition.


    %=========================================================
    \subsection{Data Analysis with \texttt{superconductivity}}
    \label{subsec:methods:digital:analysis}
    %=========================================================

        The raw measurement files produced by the measurement stack contain synchronized instrument outputs and setup metadata, but they are not yet the physical data products used in the analysis. This separation is intentional: the measurement files store the minimally processed useful record, while offset correction, time domain filtering, gridding, and smoothing are applied later with explicit parameters. I first implemented many of the basic evaluation ideas in the setup specific repository \texttt{p5control-bluefors-evaluation}~\cite{p5control_bluefors_evaluation}. For this thesis, I then developed the broader Python package \texttt{superconductivity}~\cite{aschenbrenner_superconductivity} as the evaluation layer between acquisition and interpretation. In addition to trace evaluation, \texttt{superconductivity} contains numerical models for BCS and MAR spectra, fitting routines, a graphical user interface, and a visualization pipeline. The graphical interface and visualization tools were useful for daily work but are not discussed in detail here. This section focuses on the reproducible data path from raw voltage traces to calibrated \textit{I--V} curves, derived \textit{dI--dV} spectra, uniformly sampled grids, and fitted model parameters.

        %=========================================================
        \subsubsection*{Data Evaluation}
        %=========================================================

            The evaluation converts each recorded measurement path into a calibrated \textit{I--V} curve in six steps. It selects one sweep branch, converts the recorded channels to sample voltage and current, corrects their offsets, filters the resulting time trace, resamples it, and finally bins it onto a regular voltage or current grid. This order is important because the low-pass filter operates on the ordered time trace. Binning removes that time coordinate and is therefore performed only after filtering.

            The acquisition card records the synchronized channels $V_1$, $V_2$, and $i_0$ on a common time base. The channels $V_1$ and $V_2$ contain the amplified room temperature readout voltages. The trigger channel $i_0$ identifies the offset interval and the upward and downward sweep branches. I used this channel to select one monotonic branch without inferring its boundaries from the noisy voltage ramp. Unless stated otherwise, the curves shown in this thesis use the downward branch.

            I next converted the selected branch to sample voltage and current. With voltage gains $A_1$ and $A_2$, reference resistance $R_\mathrm{ref}$, and channel offsets $V_{1,\mathrm{off}}$ and $V_{2,\mathrm{off}}$, these quantities are
            \begin{equation}
                \begin{aligned}
                    V(t) &= \frac{V_1(t) - V_{1,\mathrm{off}}}{A_1}\,, \\
                    I(t) &= \frac{V_2(t) - V_{2,\mathrm{off}}}{A_2 R_\mathrm{ref}}\,.
                \end{aligned}
                \label{eq:methods:digital:raw-iv}
            \end{equation}
            The offsets are obtained from the interval recorded before the sweep and are subtracted from every trace. This correction compensates for slow thermal drifts in the amplifier outputs. When the data contain sufficient symmetric structure, the finer symmetry based correction described below can also be applied. Both corrections are performed while the data remain an ordered pair of time traces, $V(t)$ and $I(t)$.

            The corrected branch is then low-pass filtered to suppress high-frequency pickup that is not resolved by the quasi-dc sweep. I filtered only the selected branch, which prevented discontinuities at the boundaries between the offset interval and the sweep branches from affecting the result. The standard analysis preset uses a fourth-order Butterworth filter with a \qty{43.7}{\hertz} cutoff. The filtered voltage and current traces are subsequently linearly interpolated onto a uniform time grid at \qty{137}{\hertz}. This numerical upsampling does not add independent measurements. It provides a denser representation of the filtered trace and regularizes its subsequent mapping onto the voltage or current grid.

            Figure~\ref{fig:methods:digital:eva} shows the transition from the time trace to the regular data products. After filtering and resampling, the data are assigned to equally spaced voltage or current bins. For a voltage based representation, I averaged the current values whose measured voltages fell into the bin around $V_k$,
            \begin{equation}
                I(V_k) = \langle I(t_j) \rangle_{V(t_j) \in [V_k-\Delta V/2, V_k+\Delta V/2]}\,.
                \label{eq:methods:digital:voltage-binning}
            \end{equation}
            Exchanging the axes gives the current grid representation $V(I_k)$. This representation is useful for branches with steep current changes, where a voltage grid would place many measurements within a narrow voltage interval. The regular curve can finally be smoothed with a median filter followed by Gaussian smoothing. This smoothing is applied after binning, so numerical derivatives are calculated from a regular data product rather than from the irregular time trace. All filtering, resampling, gridding, and smoothing parameters remain part of the evaluation record.

            The result is a calibrated and regularly sampled \textit{I--V} curve that remains linked to its selected sweep branch and acquisition metadata. This curve is used for plotting, numerical differentiation, and model comparison. The data can be represented as \textit{I--V} curves or as derived \textit{dI--dV} spectra and compared with the appropriate theoretical model. Each model dependent analysis therefore starts from the same reproducible data product with defined units, offsets, grids, and processing parameters.

        %=========================================================
        \subsubsection*{Offset Analysis}
        %=========================================================

            Beyond the coarse subtraction of amplifier drift, the evaluation pipeline provides an optional symmetry based correction that aligns the residual voltage and current origins. It is not applied by default, and its use and fitted offsets remain part of the evaluation record.

            The key advantage of the method is that differentiation separates the two offset coordinates. For an intrinsic point symmetric quasi-dc \textit{I--V} curve, the differential conductance is even in voltage. A constant current offset drops out when calculating \textit{dI--dV}, so the symmetry search depends on the voltage offset but not on the current offset. The remaining task is the horizontal alignment of the conductance trace. If the correct voltage origin is chosen, the derivative overlaps with its reflection. The implementation determines this alignment by minimizing a mirror symmetry error.

            In practice, the analysis scans a list of candidate voltage offsets. For a candidate $\delta V$, the trace is shifted by subtracting $\delta V$, then passed through the same filtering, resampling, binning, and smoothing pipeline as the final data. The shifted trace defines a sampled curve $I_{\delta V}(V_k)$ on a symmetric voltage grid. The score is the mean absolute mirror mismatch of its differential conductance,
            \begin{equation}
                \epsilon_V(\delta V)
                =
                \left\langle
                    \left|
                        \frac{\mathrm{d}I_{\delta V}}{\mathrm{d}V}(V_k)
                        -
                        \frac{\mathrm{d}I_{\delta V}}{\mathrm{d}V}(-V_k)
                    \right|
                \right\rangle_k\,.
                \label{eq:methods:digital:offset:vscore}
            \end{equation}
            The voltage offset assigned to the trace is the candidate with the smallest finite value of $\epsilon_V$. I then exchanged the axes and applied the same search to \textit{dV--dI}. In this representation, a constant voltage offset drops out under differentiation, while the symmetry alignment determines the current offset. The two searches therefore determine $\delta V$ and $\delta I$ independently. Subtracting both values corrects the complete origin of the measured trace in the \textit{I--V} plane.

            The procedure is a diagnostic correction, not a physical model fit. It requires corresponding conductance features at positive and negative bias and a distinct error minimum. Traces with rectification, strong hysteresis, insufficient branch overlap, or no distinct minimum are not corrected because symmetry cannot determine a unique voltage origin.

        %=========================================================
        \subsubsection*{BCS Simulation and Fitting}
        %=========================================================

            The BCS simulation predicts tunnel regime quasiparticle spectra from a set of physical parameters. The microscopic tunnel expressions were introduced in Sec.~\ref{subsec:micro:tunnel-current}. Here I describe how they are evaluated numerically and used in fits.

            The core model evaluates the SIS tunnel current from Eq.~\eqref{eq:micro:tunnel}. The two electrodes are represented by Dynes broadened BCS densities of states and finite-temperature Fermi functions. The model parameters are the normal conductance $G_\mathrm{N}$, electronic temperature $T$, zero-temperature superconducting gap $\Delta_0$, and Dynes broadening $\gamma$.

            For repeated evaluations, the production model uses the convolution form of the tunnel current, Eq.~\eqref{eq:micro:tunnel-conv}. Instead of recomputing the full energy integral for every bias point, the occupied and empty spectral functions are convolved on an energy grid and interpolated back to the requested voltage axis. This makes parameter sweeps and fits substantially faster while keeping the same physical model.

            Photon assisted tunneling is included by applying the Tien--Gordon sideband sum of Eq.~\eqref{eq:micro:pat-iv} to the BCS current. This extension adds the irradiation amplitude $A$ and frequency $\nu$ as model parameters. After evaluating the static or photon assisted current $I_0(V)$, the model can account for unresolved voltage fluctuations by averaging over a Gaussian distribution of instantaneous bias offsets $\delta V$,
            \begin{align}
                I_{\sigma_V}(V)
                = \int_{-\infty}^{\infty}
                \frac{\mathrm{d}(\delta V)}{\sqrt{2\pi}\sigma_V}
                \exp\!\left[-\frac{(\delta V)^2}{2\sigma_V^2}\right]
                I_0(V+\delta V)\,,
                &&
                \delta V\sim\mathcal{N}(0,\sigma_V^2)\,.
                \label{eq:methods:digital:bcs:voltage-broadening}
            \end{align}
            Here $\sigma_V$ is the standard deviation of the voltage offset distribution, not its full width at half maximum. The corresponding full width is $2\sqrt{2\ln 2}\,\sigma_V$. The implementation evaluates $I_0$ on a voltage grid extended by six standard deviations on either side, performs the normalized Gaussian convolution, and interpolates the broadened current back to the requested bias points. Numerical derivatives used for the simulated \textit{dI--dV} and \textit{dV--dI} curves are obtained from this broadened \textit{I--V} curve.

            The parameter $\sigma_V$ is an effective instrumental broadening rather than a microscopic property of the junction. It represents bias fluctuations that are not resolved during the acquisition of one data point and can also absorb broadening caused by averaging over a changing bias within the measurement bandwidth. It differs from the electronic temperature $T$, which changes the Fermi occupations, and from the Dynes parameter $\gamma$, which broadens the quasiparticle density of states and introduces subgap spectral weight. These mechanisms can still be correlated in a fit. The fitting interface therefore allows $\sigma_V$ to be optimized together with the other model parameters or fixed to an independently determined value or a value obtained from a reference trace, depending on the purpose and constraints of the analysis.

            The fitting interface was designed so that each model parameter can either be optimized or kept fixed. This is important for data sets containing many \textit{I--V} spectra, where global parameters such as $\Delta_0$, $\gamma$, $G_\mathrm{N}$, $\nu$, or $\sigma_V$ may be determined independently or from a reference trace and then held constant while only $T$ or $A$ is fitted for each spectrum. Fixing well-constrained parameters reduces correlations between fit parameters and makes the extracted trends easier to interpret.

            Repeated fits require many evaluations of the same model over complete data sets. I therefore used the JAX backend for vectorized evaluation with just in time compilation~\cite{jax2018github}. Together with the convolution kernel, this reduced typical fitting tasks to minutes on a standard laptop. A direct NumPy implementation was retained as a transparent numerical reference.

            The resulting fits should be interpreted as tunnel regime quasiparticle fits. They return effective parameters within the BCS-Dynes description, but they do not describe finite transmission MAR, coherent supercurrent dynamics, Coulomb blockade, or environmental phase fluctuations.

        %=========================================================
        \subsubsection*{MAR Simulation}
        %=========================================================

            The MAR simulation predicts finite transmission spectra of atomic contacts from the channel transmissions and the remaining model parameters. The physical model is described in Sec.~\ref{subsec:meso:mar}. Here I describe only the numerical layer used for evaluation. The core calculations were based on three compiled Fortran backends from Juan Carlos Cuevas: a symmetric Hamiltonian approach solver, an asymmetric Hamiltonian approach solver, and a full counting statistics (FCS) solver. The two Hamiltonian approach solvers evaluate the dc MAR current described in Ref.~\cite{cuevas_hamiltonian_1996}, while the FCS backend gives the charge resolved decomposition of Ref.~\cite{cuevas_full_2003}. I did not modify these numerical kernels.

            My contribution was the shared Python layer around all three backends. This layer handled units, model dispatch, temperature dependent gaps, deterministic HDF5 caching, odd symmetry reconstruction, segmented backend calls, and parallel evaluation. The user facing parameter was the zero-temperature gap, while the backend was called with the temperature dependent gap. This was important when temperature was scanned or fitted, because a change in $T$ affects both the Fermi occupations and the MAR voltage scale.

            The reason for this additional layer was the high computational cost. In my evaluation environment, an uncached single-channel calculation on a sufficiently resolved voltage grid typically took a few tens of seconds with the symmetric Hamiltonian approach backend, about one to two minutes with the asymmetric backend, and about ten minutes with the FCS backend. Dense parameter scans would therefore be impractical if every voltage grid and parameter point were evaluated from scratch. The wrapper reduced this cost without changing the physical model: symmetric electrodes were sent to the faster symmetric backend, asymmetric electrodes to the asymmetric backend, and charge resolved calculations to the FCS backend only when needed. Cached curves were indexed by normalized model parameters and voltage axes, so numerically equivalent floating point inputs mapped to the same entry instead of creating duplicate curves. Since the dc \textit{I--V} curve is point symmetric, only positive voltages were evaluated and cached, while the negative branch was reconstructed.

        %=========================================================
        \subsubsection*{MAR Fitting}
        %=========================================================

            To determine the mesoscopic pincode $\{\tau_i\}$ of an atomic contact, I fitted the measured finite transmission \textit{I--V} characteristic with a sum of independent single-channel MAR currents. The adjustable parameters were the channel transmissions $\{\tau_i\}$, the zero-temperature gap $\Delta_0$, and the effective voltage noise width $\sigma_V$. 
            
            I fixed the electronic temperature and Dynes broadening to $T=0$ and $\gamma=0$. The effective voltage noise width $\sigma_V$ already accounts phenomenologically for the rounding relevant to these fits. Allowing additional broadening through $T$ or $\gamma$ would introduce strongly correlated parameters that cannot be distinguished reliably at the available voltage and current resolution. The fitted transmissions should therefore be interpreted within this restricted zero-temperature model rather than as an independent determination of electronic temperature or lifetime broadening.
            
            Each adjustable parameter could be varied within prescribed bounds on a predefined grid or fixed to a selected value. Because the transmission grid included $\tau_i=0$, a fit allowing $N$ channels also included every solution with fewer than $N$ contributing channels. Increasing the maximum number of allowed channels therefore did not require all of them to contribute to the fitted current.

            I first evaluated and cached a database of single-channel currents on a discrete grid in $\tau$ and $\Delta_0$. At every point in this grid, I applied the same Gaussian voltage convolution used for the tunnel regime model and stored the resulting curves for discrete values of $\sigma_V$. A multichannel prediction was then obtained by summing the stored currents at the selected channel transmissions. The measured current was interpolated on the voltage grid of this database. Nonfinite samples were discarded, and the central voltage interval containing the switching or supercurrent feature was masked because it is not described by the dc MAR model. Additional nonnegative point weights and voltage limits could be used to restrict the fit to informative parts of the trace.

            The fit minimized a weighted current space residual on this discrete parameter grid. If the normal-state conductance $G_\mathrm{N}$ could be determined reliably from the measured high-bias response, I restricted it to a trustworthy interval. The objective function was
            \begin{align}
                \chi^2(\{\tau_i\}, \Delta_0, \sigma_V)
                =
                \sum_{k\in\mathcal K}
                w_k \cdot
                \left(
                    I_\mathrm{exp}(V_k)
                    -
                    I_\mathrm{MAR}(V_k,\{\tau_i\}, \Delta_0, \sigma_V)
                \right)^2\,,
                \label{eq:methods:digital:mar:chi2}
            \end{align}
            where $\mathcal K$ denotes the retained voltage samples. The weights can be chosen to balance different parts of the spectrum. For example, $w_k\propto1/|V_k|$ reduces the influence of the larger absolute currents at high bias while retaining sensitivity to the subgap MAR structure. In this case, the zero-voltage point is assigned zero weight, while any finite central interval not described by the dc model is excluded through $\mathcal K$. 
            
            An exhaustive global search was not computationally feasible beyond three channels, even on a sparse transmission grid, because the number of possible pincodes grows combinatorially with the number of channels. The search therefore started from initial parameter guesses and tested all valid states reached by moving one free parameter by one grid point. It accepted the neighboring state with the largest reduction in $\chi^2$ and repeated this procedure until no tested move improved the fit. In addition to single-channel steps, paired exchange moves increased one transmission and decreased another. These moves allowed the channel decomposition to change even when a narrow constraint on $G_\mathrm{N}$ prohibited an isolated transmission step. Independent random restarts within the parameter bounds reduced the sensitivity to the initial pincode. For a sequence of contact configurations, the result of one spectrum could be used as the starting point for the next spectrum.

            This procedure is a local discrete optimization and does not guarantee the global minimum. The restarts improve robustness but do not replace a complete search of the pincode space. Allowing additional channels can introduce nearly degenerate solutions containing very weak transmissions, so the number of physically resolved channels remains limited by the data quality and transmission grid resolution. The parameter resolution is set by the database axes, and the reported values are grid points without interpolation or confidence intervals. The extracted transmissions are therefore effective channel transmissions within the coherent short-contact MAR model. The procedure does not model the dc supercurrent branch itself, environmental phase fluctuations, Coulomb blockade, or nonequilibrium heating beyond the effective parameters included in the grid.
